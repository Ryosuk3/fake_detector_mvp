# Оптимизация сборки Docker образов

## Проблемы и решения

### Проблема 1: Долгая сборка (20+ минут)

**Причина:** Установка тяжелых зависимостей (torch, transformers) занимает много времени.

**Решение:**
- Использование CPU-only версии torch (быстрее устанавливается)
- Удаление неиспользуемых зависимостей из nlp_service
- Ленивая загрузка ML моделей (при первом запуске, а не при сборке)

### Проблема 2: Ошибка загрузки spaCy модели

**Причина:** Неправильный URL при загрузке модели через subprocess.

**Решение:**
- Ленивая загрузка модели при первом использовании
- Fallback на базовую модель если загрузка не удалась
- Правильная обработка ошибок

## Оптимизации

### NLP Service
- Убраны: torch, transformers, scikit-learn, sentencepiece (не используются)
- Оставлены только необходимые: spacy, nltk, langdetect

### Verifier Service & Search Service
- Используется CPU-only версия torch (устанавливается отдельно)
- sentence-transformers устанавливается после torch

### Общие оптимизации
- Модели загружаются при первом запуске, а не при сборке
- Использование `--no-cache-dir` для pip
- Очистка apt кэша после установки системных пакетов

## Ожидаемое время сборки

- **Backend**: ~1-2 минуты
- **Frontend**: ~2-3 минуты
- **NLP Service**: ~2-3 минуты (было 30+ минут)
- **Search Service**: ~5-7 минут (torch + sentence-transformers)
- **Verifier Service**: ~5-7 минут (torch + sentence-transformers)

**Итого: ~15-20 минут** (вместо 30+ минут)

## Первый запуск

При первом запуске контейнеров модели загрузятся автоматически:
- spaCy ru_core_news_sm: ~50MB
- sentence-transformers: ~400MB

Это займет дополнительно 2-5 минут при первом запросе.
